# AWG Rule-Set Helper

Небольшое расширение для Google Chrome, которое управляет rule-set'ами [AWG Manager](https://github.com/hoaxisr/awg-manager) через его HTTP API: добавляет домены в наборы, редактирует содержимое и проверяет соединение — без захода в веб-интерфейс.

## Возможности

- **Быстрое добавление домена** в выбранный inline-rule-set одной кнопкой (или Enter в поле ввода).
- **Автоподстановка домена активной вкладки** в поле «Домен или URL».
- **Отдельная страница-редактор** содержимого выбранного набора (Pretty JSON, Ctrl/Cmd+S для сохранения).
- **Проверка соединения** (GET `/rulesets/list`) с выводом результата рядом с кнопкой.
- **Контекстное меню**: ПКМ по странице или ссылке → «Добавить домен … в rule-set AWG».
- **Отслеживание неудачных запросов**: расширение показывает домены, к которым не смогли загрузиться ресурсы. Количество неудачных запросов текущей вкладки показывается жёлтым бейджем на иконке, а в попапе — списком с чекбоксами.
- **История** добавленных доменов.
- Тёмная/светлая тема — автоматически следует за настройками Chrome.

## Установка

### Chrome / Chromium

1. Скачайте последний релиз со страницы **GitHub Releases** (например `awg-ruleset-helper-v1.0.0-chrome.zip`).
2. Откройте `chrome://extensions`.
3. Включите **Режим разработчика** (Developer mode, справа сверху).
4. Перетащите мышкой архив или распакуйте сами и нажмите **«Загрузить распакованное»** (Load unpacked) и выберите распакованную папку (ту, где лежит `manifest.json`).
> Альтернативно можно склонировать репозиторий и выбрать папку проекта — но там могут содержаться совсем непротестированные изменения.

### Firefox

Используйте архив с суффиксом `-firefox` (например `awg-ruleset-helper-v1.0.0-firefox.zip`):

1. Скачайте и распакуйте архив.
2. Откройте `about:debugging#/runtime/this-firefox`.
3. Нажмите **«Загрузить временное дополнение»** (Load Temporary Add-on) и выберите файл `manifest.json` в распакованной папке.

> Временное дополнение живёт до перезапуска Firefox. Для постоянной установки соберите подписанный `.xpi` через AMO (или сторонний подписчик).

## Быстрый старт

1. Нажмите на иконку расширения в панели инструментов.
2. В блоке «Настройки» укажите:
   - **Base URL (API)** — например `http://192.168.1.1:2222/api`;
   - **API Key** — если в AWG Manager включена авторизация (Берется из: Настройки → Расширенные → «API Key»);
   - **Раздел API** — `FakeIP config` или `Router` в зависимости от того, где создан ваш набор;
   - **Тег rule-set** — выберите нужный inline-набор из списка (кнопка «Обновить список»).
3. Нажмите **«Проверить»** — при успехе покажет количество найденных наборов.
4. В блоке **«Игнорировать при подсчёте ошибок»** отметьте inline-наборы, домены которых не должны попадать в «Неудачные запросы» (например, rule-set с рекламными домеными).
5. Нажмите **«Сохранить»**, чтобы запомнить настройки.

### Добавление домена

Введите домен или URL (например `rutracker.org` или `https://tracker.site`) и нажмите «Добавить в rule-set». Домен будет добавлен в выбранный набор (по умолчанию `domain_suffix` — вместе со всеми поддоменами; точный матч включается настройкой «Матчинг» → `domain`).

Домен активной вкладки подставляется автоматически при открытии попапа.

### Контекстное меню

ПКМ по любой странице или ссылке → «Добавить домен … в rule-set AWG». Результат придёт системным уведомлением.

### Неудачные запросы

Расширение слушает `webRequest.onErrorOccurred` и запоминает домены, загрузка ресурсов с которых не удалась, вместе со страницей, на которой это произошло. В попапе в разделе «Неудачные запросы» показываются **только неудачи текущей открытой вкладки** (домен страницы указан в подписи):

- на иконке расширения жёлтый бейдж показывает суммарное число неудачных запросов текущей вкладки и обновляется при ошибках/смене вкладки;
- у каждого домена в списке показывается причина: сетевые ошибки (`net::ERR_*`), HTTP-ошибки (`HTTP 4xx/5xx`);
- отметьте чекбоксами нужные домены (счётчик повторных ошибок показывается как ×N);
- нажмите **«Добавить выбранные»** — домены попадут в выбранный rule-set, как и при быстром добавлении;
- кнопка **«Очистить»** стирает весь кэш.

Кэш хранится локально в `chrome.storage.local` (`failedDomains`, до 100 записей); неудачи с других страниц и запросы самого расширения не отображаются, но остаются в кэше.

### Редактор содержимого

Кнопка **«Редактор»** в шапке попапа открывает отдельную вкладку:

- выберите набор и нажмите «Загрузить содержимое»;
- отредактируйте JSON-массив правил `rules`;
- «Сохранить содержимое» валидирует JSON и сохраняет через `/update`; после сохранения содержимое перезагружается с сервера;
- `Ctrl/Cmd+S` — быстрый способ сохранить.

## Настройки

| Параметр              | Описание                                                                 |
| --------------------- | ------------------------------------------------------------------------ |
| `Base URL (API)`      | Адрес API AWG Manager, например `http://192.168.1.1:2222/api`.           |
| `API Key`             | Bearer-токен из Настроек AWG Manager (если включена авторизация).        |
| `Раздел API`          | `singbox/fakeip/config/rulesets/*` или `singbox/router/rulesets/*`.      |
| `Тег rule-set`        | Тег inline-набора; список грузится из API (кнопка «Обновить список»).    |
| `Матчинг`             | `domain_suffix` (домен + поддомены) или `domain` (только точный домен).  |
| `Игнорировать при подсчёте ошибок` | Чекбокс-список inline-наборов; домены отмеченных наборов не учитываются в «Неудачных запросах». |

Все значения хранятся локально в `chrome.storage.local` и никуда не отправляются, кроме указанного Base URL в качестве API-запроса.

> Домены отмеченных наборов кэшируются локально (`ignoreDomains`): учитываются `domain`, `domain_suffix` (домен + поддомены) и `domain_regex`. Обновляются при изменении отметки и списка наборов.

## Упрощение host_permissions

По умолчанию в `manifest.json` открыт доступ ко всем адресам. Для безопасности можно ограничить:

```json
"host_permissions": ["http://192.168.1.1:2222/*"]
```

(замените на адрес вашего роутера/AWG Manager).

## Права расширения

- `storage` — хранение настроек и истории;
- `tabs` — чтение URL активной вкладки для автозаполнения домена;
- `contextMenus` — пункты контекстного меню;
- `notifications` — уведомления о результате из контекстного меню;
- `webRequest` — слежение за неудачными запросами (только наблюдение, не блокировка).

## Примечания и ограничения

- Расширение **заменяет содержимое набора целиком** при сохранении (так устроен API `/update`), поэтому перед добавлением домена оно сначала читает текущий список правил.
- В rule-set'ах sing-box (включая inline) нельзя использовать matcher `protocol` — его поддерживают только `route.rules`/`dns.rules`. Для таких правил используйте слот конфигурации `90-user.json` в самом AWG Manager.
- Если расширение перестало работать — проверьте, не изменился ли формат API AWG Manager, и порог авторизации (401/403 при неверном ключе).

## Совместимость

- Manifest V3: Google Chrome / Chromium (манифест `manifest.json`) и Firefox 109+ (манифест `manifest.firefox.json`, собирается в архив с суффиксом `-firefox`). Расширение не использует серверные компоненты и работает полностью локально.
- API AWG Manager: эндпоинты `GET /singbox/{fakeip/config|router}/rulesets/list` и `POST /singbox/{fakeip/config|router}/rulesets/update`.
- В Firefox 109–137 цвет текста бейджа задаётся браузером автоматически (`setBadgeTextColor` доступен с Firefox 138).
